## Problem
Everything wolluf knows comes from files osu! stable writes in its own undocumented or half-documented binary formats. The crates.io `osu-db` 0.3.0 cannot read the current osu!.db (research 01 L83/L89), the Python prototypes are oracles and not shippable, and osrparse gets replay time wrong (research 03 L111, L156). F0 needs a read-only, pure, exhaustively tested codec layer so that 003 can ingest 4,989 scores idempotently and verify replay headers, and 004 can read the cfg username. It must also find the osu! install on Windows and from WSL, and tell the app whether osu! is running. A codec that silently mis-parses corrupts the irreplaceable ledger, so every ambiguity must be a loud, typed error.

## Behaviour
- **Decoders are all-or-nothing per file.** `decode_*(bytes) -> Result<(T, Diagnostics), CodecError>`. There is no partial result: osu!.db has no per-entry length since 20191106, so a bad entry cannot be skipped safely. The error carries the file kind, the byte offset and what was expected.
- **Structural invariants checked on every decode** (any failure → `CodecError`, never a panic):
  - every `String` tag is `0x00` or `0x0b`; a ULEB128 longer than 5 bytes or a length beyond the remaining bytes is an error;
  - element counts are non-negative and `count × min_record_size ≤ remaining bytes` before any allocation, so a corrupt count cannot trigger a huge `Vec::with_capacity`;
  - osu!.db star-rating pairs start with `0x08`, and the second tag is `0x0d` (Double) below 20250107 and `0x0c` (Float) from 20250107; the wrong tag is `UnexpectedTag`, not a fallback;
  - osu!.db below 20191106: the entry-size int must equal the bytes the entry consumed (`EntrySizeMismatch`);
  - scores.db: the int after the timestamp is exactly −1 (`UnexpectedValue`);
  - osu!.db, scores.db and collection.db end exactly at EOF (`TrailingBytes`).
- **Version policy (ADR 0015, Accepted by the user 2026-09-28).** The header version is the osu! build that last wrote the file (scores.db per-score versions on the pilot span 20220424–20260924 across 5 builds in 6 months; collection.db is at 20260624 while the client is 20260924).
  - Below the format's minimum → `UnsupportedFormat{kind, version}` at once.
  - From the minimum up to `NEWEST_VERIFIED` → decoded with the layout the thresholds select.
  - Newer than `NEWEST_VERIFIED` → decoded with the newest layout **only if** every structural invariant above holds, including exact EOF (for `.osr`: exactly the expected trailing bytes after the payload); the result then carries the warning `format.unverified_version`. Any invariant failure on such a file is reported as `UnsupportedFormat` (not `PARSE_FAILED`), because the likeliest cause is a layout change.
  - `.osr`/score record versions ≥ 30000000 are lazer exports and are `UnsupportedFormat`.
- **osu!.db** → `OsuDb {version, folder_count, account_unlocked, unlock_ticks, player_name, beatmaps, permissions}`. Each `OsuDbBeatmap` keeps every field of the wiki table (`legacy_db.md`), including the four star-rating lists as `(mods: i32, sr: f64)` (Float values widened losslessly), timing points `(bpm, offset, uninherited)`, grades, booleans as raw bytes, and ticks as raw `i64`. Accessors: `beatmap_md5() -> Option<ChartMd5>` (None if absent, empty or not 32 lowercase hex, with diagnostic `osu_db.bad_md5`), `mania_keymode() -> Option<Keymode>` (`mode == 3` → `round(CS)`, via `Keymode::new`). Unknown ranked status (> 7) and unknown mode (> 3) are diagnostics, not errors.
- **scores.db** → `ScoresDb {version, beatmaps: Vec<ScoresDbBeatmap{md5: OsuString, scores: Vec<ScoreRecord>}>}`. `ScoreRecord` = shared `ScoreHeader` (mode, version, beatmap md5, player, replay md5, `counts: JudgementCounts {n300, n100, n50, geki (MAX), katu (200), miss}` (`u16` each; a pub type 006 reuses for `.osg`), score `i32`, max combo `u16`, perfect raw `u8`, mods `u32`, life bar, `timestamp_ticks: i64`) + `online_id: OnlineId` + `target_practice: Option<f64>`.
  - Online id width follows the record's own version: ≥ 20140721 → `i64`, 20121008–20140720 → `i32`, older → absent (lazer `LegacyScoreDecoder`, fetched 2026-09-28). `OnlineId::positive() -> Option<u64>` treats ≤ 0 as none (4,718 of 4,989 pilot scores are 0).
  - Target Practice (`mods & 1<<23`) adds an `f64`.
  - `player` is an `OsuString`: the pilot has 1,395 present-but-empty names (`0x0b 0x00`) and 0 absent ones; both states round-trip distinctly so 004 can decide how to key them. Non-UTF-8 bytes are preserved.
- **collection.db** → `CollectionDb {version, collections: Vec<Collection{name: OsuString, beatmap_md5s: Vec<OsuString>}>}`. `encode_collection_db(&CollectionDb) -> Vec<u8>` writes minimal ULEB128 and is the exact inverse of decode for any value decode produces.
- **`.osr`** → `decode_osr(bytes) -> OsrFile {header: ScoreHeader, payload: Option<Range<usize>>, online_id, target_practice}`.
  - The compressed length is an `i32`; ≤ 0 → `payload: None` + diagnostic `osr.empty_payload` (3 pilot files of 126 bytes with a non-zero online id); a length beyond EOF → `Truncated`.
  - After the payload: online id (same version rule) and the TP `f64`; anything left over → diagnostic `osr.trailing_bytes` (pilot: exactly 8 trailing bytes in 5,030/5,030 files, i.e. only the online id).
  - `check_name_consistency(&ReplayFileName, &ScoreHeader) -> Diagnostics`: header md5 ≠ name md5 → `osr.name_md5_mismatch`; `DotNetTicks(timestamp_ticks).to_filetime() ≠ Some(filetime)` → `osr.name_time_mismatch`.
- **`Data/r` names.** `ReplayFileName::parse(&str) -> Option<ReplayFileName{md5: ChartMd5, filetime: core::FileTime, kind: Osr|Osg}>` accepts exactly `^[0-9a-f]{32}-[0-9]{1,19}\.(osr|osg)$` with `filetime` fitting `i64`. Uppercase hex, `.osr.tmp`, missing or other extensions → `None`. `format()` is the inverse. It is the only `Data/r` name parser in the workspace: 003's `replay_dir::index` calls it. Ticks ↔ FILETIME conversion is 001's core `DotNetTicks::to_filetime` / `FileTime::to_dotnet_ticks`; this crate adds none.
- **cfg.** `list_user_cfgs(root) -> Vec<CfgFile{path, account: String, mtime}>` returns files matching `osu!.<account>.cfg` (not `osu!.cfg`), newest mtime first. The `<account>` part is the Windows account name, not an osu! name (pilot: `twulfz`). `parse_user_cfg(bytes) -> (UserCfg{username: Option<String>, beatmap_directory: Option<String>}, Diagnostics)`:
  - lines are `Key = Value` (pilot: CRLF, no BOM; a UTF-8 BOM is tolerated); the key is compared case-insensitively against the allowlist **before** the value is touched; non-allowlisted lines (including `Password`) are skipped without copying their value anywhere;
  - the value is trimmed of ASCII whitespace at both ends only (`Username = TWulfZasdasdasd d jSS||` → `TWulfZasdasdasd d jSS||`); an empty value → `None`;
  - `#` comment lines are ignored; a line without `=` → `cfg.malformed_line`; a repeated allowlisted key → last wins + `cfg.duplicate_key`;
  - diagnostics carry line numbers only, never line content.
  - `read_user_cfg(path)` reads, parses and drops the buffer. The cfg is never vaulted or hashed as a whole (003 already keeps cfg out of `source_snapshot`).
- **Install detection** (single owner; 005's setup service and CLI only call it).
  - `DetectEnv::from_system()` (IO) gathers platform (`Windows | Wsl | Linux | Other`; WSL = `/proc/sys/fs/binfmt_misc/WSLInterop` exists or `WSL_DISTRO_NAME` is set), env `WOLLUF_OSU_DIR`, `LOCALAPPDATA`, `ProgramFiles`/`ProgramFiles(x86)`, drive roots (Windows `C:\`…`Z:\` that exist; WSL `/mnt/[a-z]` directories), on WSL `/mnt/c/Users/*` except `Public`, `Default`, `Default User`, `All Users`, and the registry value `HKCR\osustable.File.osz\shell\open\command` (Windows: `winreg`; WSL: `/mnt/c/Windows/System32/reg.exe query …` through interop, killed after `ProbeParams.timeout`). On the pilot that value is `"E:\Games\osu!\osu!.exe" "%1"` (verified 2026-09-28 by 005); `HKCR\osu` does not exist there. A source that fails is logged at debug and skipped.
  - `candidate_roots(&DetectEnv) -> Vec<Candidate{root: PathBuf, source: CandidateSource}>` is pure, deduplicated (case-insensitively on Windows and drvfs, first source wins) and ordered: `env` (`WOLLUF_OSU_DIR`); `registry` (parent of the exe in the open command, parsed by pure `parse_open_command`, translated on WSL); `local_app_data` (`<LOCALAPPDATA>/osu!`); `wsl_user_profile` (each `<u>/AppData/Local/osu!`); `drive_scan` (each drive `<d>/osu!` then `<d>/Games/osu!`); `program_files` (each `<pf>/osu!`). `CandidateSource` is a stable string enum. The pilot is found by `registry` and again by `drive_scan`.
  - `validate_install(path, &DetectEnv) -> Result<InstallInfo, SourceError>`: a path to `osu!.exe` or any file is normalised to its parent directory; on WSL a Windows path (`E:\Games\osu!`) is translated first; the directory must contain `osu!.db` and `osu!.exe` (names matched case-insensitively). `client.realm` without `osu!.db` → `LazerInstall{path}` (maps to `UNSUPPORTED_FORMAT`, message key `setup.error.lazer_not_supported`). Other missing markers → `InvalidInstall{path, missing}` (maps to `OSU_DIR_NOT_FOUND`). A missing `scores.db` does not invalidate (fresh install) and is reported through `has_scores_db`. `InstallInfo {root, osu_db_version: i32 (first 4 bytes, read-only open), has_scores_db, has_collection_db, has_data_r, user_cfgs, songs_dir}`; `songs_dir` comes from the newest cfg's `BeatmapDirectory` (relative → under root; absolute Windows path → translated on WSL) or `<root>/Songs`.
  - `detect(&DetectEnv) -> Vec<(Candidate, Result<InstallInfo, SourceError>)>` validates every candidate in candidate order and returns invalid ones too, so the UI can say why (005 maps them to `valid: false`). No candidate → empty vec (005 asks for a path).
- **osu!-running probe.** `trait OsuProcessProbe: Send + Sync { fn probe(&self) -> ProbeResult }` with `ProbeResult::{Running{pids}, NotRunning, Unknown{reason}}`.
  - `SysinfoProbe` (Windows and native Linux): process name equals `osu!.exe` or `osu!`, case-insensitive.
  - `WslTasklistProbe`: runs `tasklist.exe /FI "IMAGENAME eq osu!.exe" /FO CSV /NH` through WSL interop, waits at most `ProbeParams.timeout` (default 3 s) and kills it after; output goes through the pure `parse_tasklist_csv`. Spawn failure, timeout or unparseable output → `Unknown`.
  - `default_probe(&DetectEnv) -> Box<dyn OsuProcessProbe>` picks by platform. Callers must treat `Unknown` as "may be running" (F4 export gate); this crate does not decide policy.
- **Errors.** `CodecError` (pure codecs) and `SourceError` (IO helpers, wraps `CodecError`) are `thiserror` enums with precise variants: `UnsupportedFormat{kind, version}`, `Truncated{kind, offset, needed}`, `BadStringTag{kind, offset, tag}`, `UnexpectedTag{kind, offset, expected, found}`, `UnexpectedValue{kind, offset, field}`, `InvalidCount{kind, offset, count}`, `Uleb128Overflow{kind, offset}`, `EntrySizeMismatch{offset, declared, consumed}`, `TrailingBytes{kind, offset, remaining}`, `Io{path, kind}`, `InvalidInstall{path, missing}`, `LazerInstall{path}`. `code() -> core::ErrorCode`: `UnsupportedFormat` and `LazerInstall` → `UNSUPPORTED_FORMAT`; other codec errors → `PARSE_FAILED`; `InvalidInstall` and `Io(NotFound)` on an install root → `OSU_DIR_NOT_FOUND`; other IO → `INTERNAL`. `is_possibly_torn_write()` is true for `Truncated` and `TrailingBytes` only.

## Domain rules
- R1 osu! folder is read-only: this crate contains no fs write, rename, copy, create-dir or permission call in `src/**` (D9; 001 check-layers L6 source-osu token list). Encoders return `Vec<u8>`; `FakeInstall` returns a file map that tests write themselves. L6 scans `src/**` including `#[cfg(test)]` modules, so every test that writes a fake tree lives in `tests/*.rs`.
- R2 Unknown or out-of-range DB format versions are a hard, explicit error; parsers are otherwise lenient through a Diagnostics collector (§7). ADR 0015 defines "unknown" as below the minimum, lazer-range, or newer-and-structurally-invalid; the reason is that the header carries the client build and changes on every osu! update (pilot scores.db per-score versions: 20220424 … 20260924, five builds since 2026-04).
- R3 osu!.db layout: `legacy_db.md` table; entry-size int only below 20191106; star ratings Int-Double below 20250107 and Int-Float from 20250107 (research 01 L83, `legacy_db.md`); pilot osu!.db 20260924 has 22,336 entries, 249,480 pairs all tagged `0x08/0x0c`, permissions 0 and no trailing bytes (measured 2026-09-28 with `rejudge/osudb.py`).
- R4 osu-db 0.3.0 on crates.io cannot read the current osu!.db; wolluf uses its own codec validated against the Python oracles (CLAUDE.md, research 01 L89, research 02 L185).
- R5 scores.db layout per `legacy_db.md` and `audit/osudb.py::read_scores_db`; many scores per beatmap md5 (research 03 L221/L230); life bar is always empty in scores.db (pilot: 0 of 4,989 non-empty) but present in `.osr`.
- R6 `.osr` layout per `osr_wiki.md`; payload is LZMA_ALONE (research 03 L136); online id width by version and the lazer ≥ 30000001 extra block from lazer `LegacyScoreDecoder` (fetched 2026-09-28). Frame time accumulation and fix-ups are F2's and must follow `rejudge.py::read_osr` (research 03 L111, L156, L167), not osrparse.
- R7 `Data/r` naming is `<beatmap md5>-<FILETIME>.osr|.osg`, FILETIME = header ticks − 504 911 232 000 000 000 (research 03 L161, L168: 4362/4362; re-measured 2026-09-28: 5,030/5,030, 0 md5 mismatches).
- R8 Failed plays are saved on client 20260924 (research 03 L115, L160); the codecs therefore never assume a score is a pass.
- R9 The cfg `Username` can be garbage (`TWulfZasdasdasd d jSS||`), so it is returned verbatim and interpreted only by 004's session-user match (004 R5). The cfg also holds a `Password` line (pilot: yes); its value must never be read into memory owned by wolluf, logged, hashed or persisted (G6: privacy by construction).
- R10 Alias raw bytes are the key and `""` is a valid alias (§5.3); codecs never normalise, trim or re-encode names.
- R11 osu!.db resolves md5 → folder/file (research 03 L131, L137); Songs as a fallback for maps missing from osu!.db is F1 (scanner moved out).
- R12 Only edges in §4 / 001's `layers.toml`: `wolluf-source-osu → wolluf-core` (F0 shortcut while `engine` does not exist); never `store` or `app` (D7).
- R13 Traits only where D8 allows: `OsuProcessProbe` is named in D8. No `GameSource` trait (§9.5: only when a second game exists). Codecs are free functions.
- R14 Real beatmaps, replays and DBs are never committed; fixtures are minimized and anonymized or synthetic (CLAUDE.md, §10).
- R15 No GPL/LGPL in-process (D16). Deps beyond core: `sysinfo` MIT, `winreg` MIT, `notify` CC0-1.0 (already in 001's allowlist); all pinned by 001 T1.

## Design
- **Crate** `crates/source-osu` (`wolluf-source-osu`), deps: `wolluf-core` (`ChartMd5`, `Keymode`, `ErrorCode`), `thiserror 2.0.21`, `md-5 0.11.0`, `sysinfo 0.39.6` (`default-features = false, features = ["system"]`; MSRV 1.95 ≤ toolchain 1.98), `winreg 0.56.0` (`[target.'cfg(windows)'.dependencies]`), `tracing 0.1.44`; all pinned by 001 T1. 003 adds `sha2`, `notify`, `notify-debouncer-full` for its modules. Dev: `proptest 1.11.0`, `insta 1.48.0`, `tempfile 3.27.0`. Features: `test-support` (encoders, builders, `FakeInstall`, `FakeProbe`; used by this crate's tests, 003/004 tests and xtask). No `unsafe` (workspace lint).
  - Process probe choice: `sysinfo` because the workspace denies `unsafe_code`, which rules out calling ToolHelp32 through `windows-sys` ourselves.
- **Modules**
  - `codec::reader` / `codec::writer` (pub, 006 reuses them): `Reader<'a>` with `u8, u16, i16, u32, i32, i64, f32, f64, uleb128, osu_string, bytes(n), count(min_size), position, remaining, expect_eof`; `Writer` mirrors it with minimal ULEB128. `OsuString::{Absent, Present(Vec<u8>)}` with `as_bytes`, `to_string_lossy`.
  - `codec::version`: `FileKind` (stable string ids `osu_db`, `scores_db`, `collection_db`, `osr`, `cfg`; 006 appends `osg`), `VersionPolicy{min, newest_verified}` per kind, `classify(kind, version) -> VersionClass::{TooOld, Verified, Unverified, Lazer}`. Constants: osu!.db min 20140609, entry-size removed at 20191106, Int-Float at 20250107, newest verified 20260924; scores.db min 20140609, newest verified 20260924; collection.db min 20140609, newest verified 20260624; score/replay online id thresholds 20121008 and 20140721; lazer from 30000000.
  - `codec::osu_db`, `codec::scores_db` (+ `codec::score_header`, shared with `.osr`), `codec::collection_db` (decode + pub encode), `codec::osr`, `codec::cfg`, `codec::replay_name`.
  - `diag`: `Diagnostics(Vec<Diagnostic{code: DiagCode, offset: Option<u64>, line: Option<u32>, detail: String}>)`. `DiagCode` is a closed enum with stable dotted strings, never renumbered: `format.unverified_version`, `osu_db.bad_md5`, `osu_db.unknown_ranked_status`, `osu_db.unknown_mode`, `osr.empty_payload`, `osr.trailing_bytes`, `osr.name_md5_mismatch`, `osr.name_time_mismatch`, `cfg.malformed_line`, `cfg.duplicate_key` (append-only; 006 appends its `osg.*` codes). `detail` holds offsets, counts and versions only: no names, paths or cfg values.
  - `error`: `CodecError`, `SourceError`, `code()`, `is_possibly_torn_write()`.
  - `paths`: pure `windows_to_wsl(&str) -> Option<PathBuf>` (drive-letter paths only; UNC → None), `is_drvfs_path(&Path) -> bool` (`/mnt/<a-z>/…`), `resolve_songs_dir(root, beatmap_directory, platform)`.
  - `install`: `Platform`, `DetectEnv` (+ `from_system`, registry read), `Candidate`, `CandidateSource`, `parse_open_command`, `candidate_roots`, `validate_install`, `detect`, `InstallInfo`.
  - `cfg_files`: `list_user_cfgs`, `read_user_cfg`.
  - `probe`: trait, `SysinfoProbe`, `WslTasklistProbe`, `parse_tasklist_csv`, `ProbeParams`, `default_probe`.
  - `testkit` (feature `test-support`): `encode_osu_db`, `encode_scores_db`, `encode_osr` (embeds the given payload bytes verbatim), `OsuDbBuilder`, `ScoresDbBuilder`, `OsrBuilder`, `FakeInstall::files() -> BTreeMap<PathBuf, Vec<u8>>` (osu!.exe stub, DBs, cfg, `Data/r`, `Songs`), `FakeProbe`. 006 adds `encode_osg`.
- **Oracle harness**: `research/scripts/oracle/dump.py <corpus> <out_dir>` imports `rejudge/osudb.py::parse`, `audit/osudb.py::{read_scores_db, read_osr_header}` and writes JSONL (`osu_db`, `scores_db`, `osr_headers`). It adds no parsing logic of its own. Corpus tests run it with `PYTHONDONTWRITEBYTECODE=1` into a tempdir (so no `__pycache__` lands in `research/`) and compare field by field.
- **Fixtures** (`cargo xtask fixtures [dbs|synthetic] --corpus <path>`; xtask gains a dependency on `wolluf-source-osu[test-support]`; 001's `layers.toml` lists this tool edge):
  - `dbs`: decode the corpus DBs, select deterministically (sorted by original md5): 12 osu!.db entries (≥ 1 per mode 0–3, mania keymodes 4 and 7, one with timing points, one per ranked status seen), the scores of those beatmaps (≤ 40; must include an empty-name score, a ScoreV2 score, a score with non-zero online id), and 2 collections restricted to them. Anonymize: every md5 → `md5("wolluf-fixture:<n>")`, consistent across the three files; every string (artist, title, creator, difficulty, audio, file, folder, source, tags, font, collection names) → `<field>-<n>`; players → `player-01…` by first appearance, `""` kept; osu!.db header name → `fixture`; online ids → 0 or `1000+n`; timing points ≤ 3 per entry. Version headers are kept. Output `fixtures/dbs/{osu_db/osu-20260924.min.db, scores_db/scores-20260924.min.db, collection_db/collection-20260624.min.db, MANIFEST.toml}` (selection rule, anonymization rule, sha256 of each file). Generation fails if any original md5 or player name (other than `""`) occurs in the output bytes.
  - `synthetic`: 4 `.osr` from `OsrBuilder` (opaque payload bytes, empty payload, Target Practice, ScoreV2 + non-zero online id) into `fixtures/synthetic/osr/`.
  - Older layouts (osu!.db 20191105 with entry sizes, 20250106 Int-Double, 20140609 minimum) have no corpus source and are built by the `test-support` encoders inside tests.
- **Versioned stages**: none. Codecs are adapters, not engine stages; the stage that consumes them (003 `catalog`, VERSION 1) bumps its own VERSION if decoded fields change. No param-pack sections (operational limits such as `ProbeParams` are plain config structs with defaults, not algorithm thresholds).

## Risks / open questions
- **Resolved (user decision 2026-09-28) — Q1:** a DB whose header is newer than the newest verified build is accepted after full structural validation, with the `format.unverified_version` warning. ADR 0015 is Accepted. The rejected alternative (strict reading of §7) would break sync on every osu! update until a wolluf release. §7's sentence "unknown DB format versions are a hard error" gets the ADR 0015 definition of "unknown" in the close-out architecture edit.
- R-a scores.db online-id width for records older than 20140721 is taken from lazer's `.osr` decoder, on the wiki's statement that a scores.db record equals the replay format apart from the online id. The pilot's oldest record is 20220424, so this branch is untested on real data. A wrong width cannot pass silently: the −1 marker and exact EOF checks turn it into a loud error. Verify on a veteran player's scores.db when available.
- R-c `sysinfo` enumerates all processes (≈ 10–50 ms on Windows); callers probe on demand, not in a loop.
- R-d A cfg with several `osu!.<account>.cfg` files: `songs_dir` and 004's session-user match both use the newest file.
- R-e Big libraries: osu!.db is decoded fully in memory (pilot 31.2 MB, ≈ 0.5 s in Python). A 100k-map library is ≈ 150 MB; acceptable on desktop, revisit with a streaming reader if a user reports it.
- R-f `tasklist.exe` needs WSL interop enabled; if disabled the probe is `Unknown`, which callers treat as "may be running".
- Resolved at F0 review: 003's `replay_dir::index` calls `ReplayFileName::parse`; the single core time types are 001's `DotNetTicks`/`FileTime`; install discovery (incl. the registry source from 005) is owned here; ADR numbers are final (0014 = 003, 0015 = this spec).
- R-g The registry source needs `reg.exe` through WSL interop on WSL; if interop is disabled that source is skipped and `drive_scan` still finds standard layouts.

**Codecs (T3–T10):**
- T5: `ReplayFileName::parse` rejects leading zeros in the FILETIME (via core's canonical parser), so `format(parse(s)) == s`.
- T8: the osu!.db ids are named for what they are: `beatmap_id` is the first Int (the `/b/` id the wiki calls "Difficulty ID"), `beatmapset_id` the second. The Python oracle's `bid` is the set id, so AC14 compares `bid` with `beatmapset_id` (a mutation against `beatmap_id` gives 19,840 mismatches). Below 20191106 the entry-size Int is assumed to exclude itself; no corpus file verifies it, and a wrong guess fails as `EntrySizeMismatch`, never silently. The osu!.db encoder lives in `testkit`, so release builds carry no dead code.
- T9: `encode_osr(header, payload, online_id, target_practice)`; on an `Unverified` version any trailing bytes escalate to `UnsupportedFormat` (ADR 0015), on a verified one they are the `osr.trailing_bytes` diagnostic.
- T10: `list_user_cfgs` returns `Result` (an unreadable root is `Io`); the `<account>` match is case-insensitive; order is newest mtime, then path.

**Install and probe (T12–T13):**
- A missing root is `InvalidInstall{missing:["directory"]}` → `OSU_DIR_NOT_FOUND`; `SourceError::Io` is always `INTERNAL`.
- `detect()` drops guessed candidates (local app data, WSL profile, drive scan, Program Files) that do not exist; env and registry candidates are always validated and returned, even when invalid.
- `DetectEnv.wsl_mount_root` (default `/mnt`) and `paths::windows_to_wsl_under` exist for tests; `process.rs` holds a shared kill-at-deadline runner. `tests/install.rs` has `required-features = ["test-support"]`.
- `OsuProcessProbe` has an extra `name()`. `parse_tasklist_csv` treats any non-CSV line containing `:` as the localized INFO line (Spanish Windows prints it in the OEM code page).

**Oracle and corpus (T14–T15):**
- `dump.py` also writes `meta.json` and an `idx` per row. The oracle's strings are lossy (`errors='replace'`, and `''` for absent), so parity compares `to_string_lossy()` and treats Absent and `Present("")` as equal where the oracle cannot tell them apart.
- `tests/corpus.rs` carries a ~100-line flat JSON parser because source-osu has no `serde_json` dev-dep (adding `serde_json.workspace = true` would let it go). The two DB round trips need `test-support`; the workspace run gets it through feature unification (confirmed green at close without `--all-features`), and without it they panic with a message naming `--all-features`.
- The speed tests assert only in release builds. `detect_finds_corpus_install` records every entry under the root before and after detection but does not walk inside the Songs beatmap folders (minutes on drvfs). Each oracle test runs `dump.py` on a symlinked view holding only the inputs it needs.

**Fixtures (T16):**
- The AC13 tests live in **`xtask/tests/fixtures.rs`** (snapshots in `xtask/tests/snapshots/`), not `crates/source-osu/tests/fixtures.rs`: that path was outside the lane's write set. Test names match the spec. Run them with `cargo nextest run -p xtask -E 'binary(fixtures)'`; the tasks.md verify filter `test(/fixtures/)` on source-osu selects nothing. Moving the file needs its snapshots re-recorded.
- None of the 99 md5s in the pilot's 5 collections has an osu!.db entry, so the generator takes the first 2 collections and adds up to 2 dangling members with fresh fixture md5s (`max_dangling_members = 2`).
- The pilot's scores.db has one-letter names (`W`, `w`, `s`) that match any byte stream, so "no player name in the output bytes" cannot hold literally: names of ≥ 4 bytes are scanned in the raw bytes, and every name, whatever its length, is compared against every decoded string field.

Synthetic `.osr` files use fixture md5s for `replay_md5`. Both subcommands take `--out`; `dbs` falls back to `WOLLUF_CORPUS` and refuses an `--out` inside the corpus.
